Workflow

  1. Refresh — loads all documents from Paperless-NGX and shows quality scores.
  2. Select documents — tick the checkboxes for documents you want suggestions for, or use Select 25 worst unreviewed. Ticking a box only selects; it never writes anything.
  3. Generate suggestions — sends the selected documents to the LLM queue. A progress bar tracks processing; you can add more documents to the queue at any time without waiting for it to finish.
  4. Review suggestions — appears once at least one result is ready. Opens the review pane on the first document with a suggestion. Apply or reject individual fields, or use "Apply & Next" to act on the whole document and jump to the next one. Each Apply writes to Paperless-NGX immediately; the notification that follows offers Undo.
  5. Show suggestions in table — optional: adds suggestion columns to the table with per-field ✓ / ✕ buttons.
  6. Accept all suggestions for selected — bulk shortcut: writes every undecided suggestion of the ticked documents to Paperless-NGX after a confirmation.

Review pane

  • Click a row to open it. Click the backdrop or press Esc to close.
  • Each field shows the current value; suggested changes appear below with Apply / Reject buttons.
  • Tags show a diff: + additions and − removals. Manual tags (matching algorithm = none) are never suggested for removal.
  • The ‹ › arrows in the header move between documents that still have suggestions to review, without acting. The counter next to them shows your position.
  • Apply & Next → applies all remaining undecided suggestions and opens the next document with pending suggestions.
  • Reject & Next → rejects all remaining and moves to next.
  • The Model reasoning section (collapsed) shows the LLM's internal reasoning for transparency.

State & persistence

  • Apply / reject choices within a session are held in memory — they are lost on page refresh. Only the final "done" status and applied values are persisted in Paperless.
  • LLM quality scores, suggestion status, and review dates are stored as Paperless-NGX custom fields (LLM quality, Suggestion status, Metadata reviewed), so they are visible inside Paperless itself.
  • Pending / ready statuses are transient — they reset if the server restarts.
